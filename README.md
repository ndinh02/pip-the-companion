# Pip — watch together, call it together

A matchday companion for mixed rooms: one fan watching with people who are new to football. In the natural breaks of a match, Pip, a small club-neutral bird, asks the room one question about how the next play will unfold. Everyone calls it, the match answers, and Pip explains why — a plain line for newcomers, a data line for fans.

Built for the Microsoft *Inside the Game* hackathon (Premier League Studio challenge).

> **All data is synthetic.** The two teams (Harbour Lights, Copperfield), every event, every position and every statistic are generated by code in this repository. No real match, club, player or footage is used.
> **No AI runs while you watch.** Text is produced and checked before the match, saved to files, and replayed.

**Hosted demo:** https://pip-the-companion-cjcdawd7gmf8f9h2.francecentral-01.azurewebsites.net/tv (Azure App Service, Free tier, France Central — the first visit after a quiet spell takes a few seconds to wake up). Phone view: `Open phone ↗` on that page; operator view: `/console`.

## Run it locally
Needs Node 22 and Python 3.9 or newer.
```bash
cd web
npm install
npm run dev
```
Then open:
- `http://localhost:5173/tv` — the shared screen. Like live TV, nothing stops for Pip: a question opens when the ball goes dead, stays open until play restarts, and the reveal shows when the outcome happens. **Highlights** (default) jumps between moments and plays each at real speed; **Full match** runs all 90 minutes; `×1/×4/×16` speeds up; `Next ▸` jumps ahead. Only half-time pauses.
- `Open phone ↗` on that page — the phone view, in a second tab of the same browser. (With `npm run dev` there is no room server, so screen and phone talk inside one browser. The hosted demo and the production server below let real phones join by QR code.)
- `http://localhost:5173/console` — operator view: tracking, the content workflow, "Catch me lying".

## What works today
| Area | Status |
|---|---|
| Synthetic match generator, seeded and reproducible | built (`match-lab/`) |
| 5 Hz tracking of 22 players and the ball, consistent with the events | built (`match-lab/matchlab/tracking.py`) |
| Facts, "Call it!" cards, timing policy, held-back moments | built (`match-reader/`) |
| Player stats per minute from events and tracking | built (`match-reader/matchreader/players.py`) |
| Checker: numbers match the events, no betting words, no invented numbers, card schema | built |
| Content workflow: writer → checker → up to 2 retries → fixed template, with a trace and the "Catch me lying" integrity demo | built (`agents/`), **template writer only — no LLM connected yet** |
| Shared screen: TV-like 3D view of the synthetic match (three.js) with cameras — main stand, far side, behind each goal, close-up, overhead VAR with the offside line on the frame of the pass, tactical 2D — an automatic director, TV-style replays at each reveal, followed players marked in every camera; question card, added-time explainer, half-time card | built |
| Phone: answers, room tally, two-depth reveal, "Who's that?", Follow, ghost run, EN / DE / VI | built (DE / VI copy are drafts) |
| Console: tracking panel, workflow trace, held-back log | built |
| Rooms across separate devices: screen and phones on any network, by HTTP polling | built (`web/server/rooms.mjs`); rooms live in memory and expire |
| AI writer on a local model (Foundry Local) through the same checker | trial run only (`data/agent-trace-llm.json`); the shipped cards are still the reviewed templates |

## Not built yet
- **AI-written cards in the shipped match.** The local-model writer works and passes the checker, but its lines are not yet reviewed for voice, and German/Vietnamese re-voicing is not built.
- The browser side-panel extension, Match Print.

## How it fits together
```
match-lab        generate_match(seed) ──► events ──► tracking synthesizer ──► tracked events + 5 Hz positions
                                             │
match-reader     facts per moment ◄──────────┘──► moment picker (timing policy) ──► cards + held-back log
                 player stats per minute (events + tracking)
                                             │
agents           writer ──► checker (code) ──► retry ×2 ──► fixed template        (before the match)
                                             │
data/*.json      approved cards, facts, tracking, player stats, added time, workflow trace
                                             │
web              /tv (shared screen)   /play/:room (phone)   /console (operator)   (replays the files)
```
Players are simple club-neutral figures (no likenesses). Because the match is synthetic, every player's position is known exactly, so a followed player stays marked in every camera; doing that on real broadcast video would need the broadcaster's tracking data or image recognition, which this project does not attempt.

Every number a viewer sees is filled in by code from `facts` or tracking; text only carries placeholders such as `{c2_fk_cross}`.

## Rebuild the demo match (seed 43)
```bash
cd match-lab    && python3 -m matchlab.track --seed 43 --out-match ../data/tracked-seed-43.json --out-tracking ../data/tracking-seed-43.json
cd ../match-reader && python3 -m matchreader.build --in ../data/tracked-seed-43.json --out ../data/demo-match.json
python3 -m matchreader.players --seed 43 --out ../data/players.json
cd ../agents    && python3 -m pippi_agents.run --seed 43 --out ../data/agent-trace.json
cd ..           && python3 scripts/added_time.py --in data/mock-seed-43.json --out web/public/data/added-time.json
cp data/demo-match.json web/public/data/match.json; cp data/tracking-seed-43.json web/public/data/tracking.json
cp data/players.json web/public/data/players.json;  cp data/agent-trace.json web/public/data/agent-trace.json
```
(`data/mock-seed-43.json` comes from `cd match-lab && python3 -m matchlab.generate --seed 43 --out ../data/mock-seed-43.json`.)

## Tests
```bash
cd match-lab    && python3 -m unittest discover -s tests
cd match-reader && python3 -m unittest discover -s tests
cd agents       && python3 -m unittest discover -s tests
python3 scripts/test_added_time.py
cd web && npm run check:copy && npm run build
```
The same checks run in GitHub Actions on every push (`.github/workflows/ci.yml`); pushes to `main` then deploy to Azure App Service.

To run the production server locally: `cd web && npm run build && cp -r dist server/dist && node server/server.mjs` → `http://localhost:8080`.

No betting (no odds, points, streaks or rankings), no accounts, no names, no free text from viewers, no club marks or real player likenesses.
