# Pip — watch together, call it together

A matchday companion for mixed rooms: one fan watching with people who are new to football. In the natural breaks of a match, Pip, a small club-neutral bird, asks the room one question about how the next play will unfold. Everyone calls it, the match answers, and Pip explains why — a plain line for newcomers, a data line for fans.

Built for the Microsoft *Inside the Game* hackathon (challenge: The Synthetic Match Insights Engine for Premier League Studio). This is an independent entry, not affiliated with or endorsed by the Premier League or Microsoft.

> **All data is synthetic.** The two teams (Harbour Lights, Copperfield), every event, every position and every statistic are generated by code in this repository. No real match, club, player or footage is used.
> **No AI runs while you watch.** Text is produced and checked before the match, saved to files, and replayed.

**Hosted demo:** https://pip-the-companion-cjcdawd7gmf8f9h2.francecentral-01.azurewebsites.net/tv. It runs on Azure App Service (Free tier, France Central). The first visit after a quiet spell can take up to a minute to wake up. Phones join at `/play/<ROOM>` (the QR code takes you there), and the operator view is at `/console`.

## Try it in a minute
1. On a laptop or TV, open `/tv` on the hosted demo and press **Start a room**. The lobby shows a QR code, a four-letter room code and a room name (tap the name for another).
2. On a phone, scan the QR with the camera, or open the site, tap **Join a room** and type the code. Pick an animal (no names, no accounts) and a language: EN, DE or VI.
3. On the TV, press **Kick off**. The controls are **Kick off / Pause**, **Next moment** (jump to the next break), **?** (how Pip works) and **More** (speed ×1/×4/×16, Highlights or Full match, camera, language, restart, new room, open a phone view in a new tab).
4. When the ball goes dead, Pip asks the room one question. Answer on the phone (you can change your mind once). The TV shows only how many have answered, then the outcome. Each phone shows the plain explanation, plus the data line under **Why?**. When the match doesn't settle the question, Pip says **No clear answer**.
5. On the phone: **Match** keeps the conversation with Pip since kick-off and the half-time and full-time recaps (the TV stays clear at the break). **My player** follows one player: a 3D character, live stats per minute, the running path and the fastest run. **Room** has the invite link, language, animal and chime.

Like live TV, nothing stops for Pip: a question opens when the ball goes dead, stays open until play restarts, and the reveal shows when the outcome happens. **Highlights** (the default) watches the opening and then jumps between moments at real speed. Only half-time pauses.

## Run it locally
Needs Node 22 and Python 3.9 (CI uses 3.9; on the owner's Mac that is `/usr/bin/python3`).
```bash
cd web
npm install
npm run dev
```
Then open `http://localhost:5173/tv`, start a room, and use **More → Open a phone view** for a phone in a second tab. With `npm run dev` there is no room server, so the screen and the phone talk inside one browser (BroadcastChannel). To let real phones join locally, run the production server (see the end of **Tests**). `http://localhost:5173/console` is the operator view: tracking, the content workflow trace and "Catch me lying".

## What works today
| Area | Status |
|---|---|
| Synthetic match generator, seeded and reproducible | built (`match-lab/`) |
| 5 Hz tracking of 22 players and the ball, consistent with the events | built (`match-lab/matchlab/tracking.py`); full-match QA in `scripts/match_qa.py` |
| Facts, "Call it!" cards, timing policy, held-back moments, "no clear answer" rule | built (`match-reader/`) |
| Player stats per minute from events and tracking | built (`match-reader/matchreader/players.py`) |
| Checker: numbers match the events, no betting words, no invented numbers, card schema, outcome named | built (`agents/pippi_agents/checker.py`) |
| Content workflow: writer → checker → up to 2 retries → fixed template, with a trace and the "Catch me lying" integrity demo | built (`agents/`); the shipped match uses the reviewed template writer |
| AI writer on a local model (Foundry Local) through the same checker | trial run only (`data/agent-trace-llm.json`, on an earlier build of the demo match) |
| TV: home with **Resume room**, lobby with QR and code, 3D view of the match (three.js) with cameras (main stand, far side, behind each goal, close-up, overhead VAR with the offside line, tactical 2D), an automatic director, replays at each reveal, followed players marked in every camera, question card with answer counts, added-time explainer, connection alarm | built |
| Phone: join by QR, typed code or in-app Scan (with paste-link fallback; on the hosted app the in-app camera is currently blocked by the server's `Permissions-Policy` header, so it falls back); animal and language; live header (crests, score, clock); answers with one change; two-depth reveal; conversation history; half-time and full-time recaps; My player; status overlays when the TV or server drops | built (DE / VI copy are drafts) |
| Console: tracking panel, workflow trace, held-back log | built |
| Rooms across separate devices, by HTTP polling | built (`web/server/rooms.mjs`); rooms live in memory, expire after 4 h, and the TV takes its room back after a server restart |

## Not built yet
- **AI-written cards in the shipped match.** The local-model writer works and passes the checker, but its lines are not yet reviewed for voice, and German/Vietnamese re-voicing is not built.
- Rooms shared across several server instances (today: one App Service instance, memory only), and remote rooms with different stream delays.
- The browser side-panel extension, Match Print.

## Built with
- **Azure App Service** (Linux, Node 22) hosts the app and the room server (`web/server/`).
- **GitHub Actions** with `azure/webapps-deploy` handles tests, QA and the gated deploy (`.github/workflows/`).
- **Foundry Local** serves a local model for the trial AI writer (`agents/pippi_agents/llm_writer.py`).

## How it fits together
```
match-lab        generate_match(seed) ──► events ──► tracking synthesizer ──► tracked events + 5 Hz positions
                                             │
match-reader     facts per moment ◄──────────┘──► moment picker (timing policy) ──► cards + held-back log
                 player stats per minute (events + tracking)
                                             │
agents           writer ──► checker (code) ──► retry ×2 ──► fixed template        (before the match)
                                             │
data/*.json      approved cards, facts, tracking, player stats, added time, workflow trace
                                             │
web              /tv (shared screen)   /play/:room (phone)   /console (operator)   (replays the files)
```
Players are simple club-neutral figures (no likenesses). Because the match is synthetic, every player's position is known exactly, so a followed player stays marked in every camera; doing that on real broadcast video would need the broadcaster's tracking data or image recognition, which this project does not attempt.

Every number a viewer sees is filled in by code from `facts` or tracking; text only carries placeholders such as `{c2_fk_cross}`.

## Rebuild the demo match (seed 43)
```bash
cd match-lab    && python3 -m matchlab.track --seed 43 --out-match ../data/tracked-seed-43.json --out-tracking ../data/tracking-seed-43.json
cd ../match-reader && python3 -m matchreader.build --in ../data/tracked-seed-43.json --out ../data/demo-match.json
python3 -m matchreader.players --seed 43 --out ../data/players.json
cd ../agents    && python3 -m pippi_agents.run --seed 43 --out ../data/agent-trace.json
cd ..           && python3 scripts/added_time.py --in data/mock-seed-43.json --out web/public/data/added-time.json
cp data/demo-match.json web/public/data/match.json; cp data/tracking-seed-43.json web/public/data/tracking.json
cp data/players.json web/public/data/players.json;  cp data/agent-trace.json web/public/data/agent-trace.json
```
(`data/mock-seed-43.json` comes from `cd match-lab && python3 -m matchlab.generate --seed 43 --out ../data/mock-seed-43.json`.)

## Tests
```bash
cd match-lab    && python3 -m unittest discover -s tests
cd match-reader && python3 -m unittest discover -s tests
cd agents       && python3 -m unittest discover -s tests
python3 scripts/test_added_time.py
python3 scripts/match_qa.py              # full-match, frame-by-frame QA of seed 43
cd web && npm run check:copy && npm run build && node --test server/server.test.mjs
```
GitHub Actions runs these checks on every push (`.github/workflows/ci.yml`), plus the full-match QA on five freshly generated seeds. A push to `main` deploys to Azure App Service only when all of them pass.

To run the production server locally: `cd web && npm run build && cp -r dist server/dist && node server/server.mjs` → `http://localhost:8080`.
